Scoring

Is this SBOM complete enough?

Score any SBOM against the three major minimum-element frameworks — the question auditors and procurement teams keep asking. Each framework reports passed checks over total checks, plus an overall average.

sbomlyze image.json --compliance sbomlyze before.json after.json --compliance
2021 7
NTIA Minimum Elements
7 checks
Name, version, supplier, unique identifiers (PURL/CPE), dependency relationships, SBOM author, and timestamp.
All checks
  • Component Name — NTIA Minimum Elements (2021) requires the name assigned to each component by its supplier
  • Component Version — NTIA Minimum Elements (2021) requires a version identifier for each component
  • Supplier Name — NTIA Minimum Elements (2021) requires the name of the entity that creates and identifies each component
  • Other Unique Identifiers — NTIA Minimum Elements (2021) lists lookup identifiers (PURL, CPE, SWID) to include where they exist
  • Dependency Relationship — NTIA Minimum Elements (2021) requires dependency relationships covering at least all top-level dependencies
  • SBOM Author — NTIA Minimum Elements (2021) requires the entity (or tool) that created the SBOM data
  • SBOM Timestamp — NTIA Minimum Elements (2021) requires the date and time of SBOM data assembly
Aug 2025 draft 10
CISA 2025 Minimum Elements
10 checks
Adds software producer, licence information, component hash, and tool name on top of NTIA.
All checks
  • Component Name — CISA 2025 Minimum Elements requires a component name for each entry
  • Component Version — CISA 2025 Minimum Elements requires a version identifier for each component
  • Software Producer — CISA 2025 Minimum Elements requires identifying the producer of each component
  • Software Identifiers — CISA 2025 Minimum Elements requires at least one software identifier per component (PURL and CPE preferred)
  • Dependency Relationship — CISA 2025 Minimum Elements requires a dependency graph covering components and their dependencies
  • License Information — CISA 2025 Minimum Elements adds license data per component (an explicit 'unknown' is permitted)
  • Component Hash — CISA 2025 Minimum Elements adds a cryptographic hash per component where the artifact is available
  • Tool Name — CISA 2025 Minimum Elements adds the name of the tool(s) used to generate the SBOM
  • SBOM Author — CISA 2025 Minimum Elements requires the person or organization that created the SBOM (distinct from the tool)
  • SBOM Timestamp — CISA 2025 Minimum Elements requires an ISO 8601 timestamp of SBOM creation
v2.1.0, 2025 9
BSI TR-03183-2
9 checks
Requires component creator contact, SHA-512 hash, SPDX-format licences, and SBOM creator contact.
All checks
  • Component Name — BSI TR-03183-2 §5.2.2 requires a component name (or the actual filename if unnamed)
  • Component Version — BSI TR-03183-2 §5.2.2 requires a version identifier
  • Component Creator — BSI TR-03183-2 §5.2.2 requires the creator of each component (email or URL contact)
  • Unique Identifiers — BSI TR-03183-2 §5.2.4 requires identifiers such as CPE or PURL where they exist
  • Distribution Licences — BSI TR-03183-2 §5.2.2 requires distribution licences, expressed as SPDX identifiers per §6.1
  • SHA-512 Hash — BSI TR-03183-2 §5.2.2 requires a SHA-512 checksum of each deployable component
  • Dependency Relationship — BSI TR-03183-2 §5.2.2 requires per-component dependency enumeration with completeness indication
  • SBOM Creator Contact — BSI TR-03183-2 §5.2.1 requires the email address (or URL) of the SBOM creator — a tool name does not qualify
  • SBOM Timestamp — BSI TR-03183-2 §5.2.1 requires the date/time of SBOM compilation

Score presentation

≥ 90%Complete
70–89%Minor gaps
50–69%Material gaps
< 50%Not fit for audit

--compliance --json includes the full report with per-check pass/fail detail; the HTML format embeds the compliance report into the report page.

Gating compliance in CI

compliance-policy.json
{
  "min_ntia_score": 85,
  "min_cisa_score": 70,
  "min_bsi_score": 80,
  "min_overall_compliance": 75
}
$ sbomlyze image.json --policy compliance-policy.json

Setting any threshold triggers compliance evaluation without the --compliance flag, so a single policy file covers drift, licences, and completeness.
