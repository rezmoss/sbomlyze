Same version, files changed inside

scanelf 1.3.7-r2 has the same version in Alpine 3.19.9 and 3.20.10, but its binary /usr/bin/scanelf changed.

containerapk Owned-file driftdeny_owned_file_drift policyapk version orderingFile changes by owner

What happened

A version diff says scanelf did not change: 1.3.7-r2 before and after. Syft also records the hash of every installed file and which package owns it, and sbomlyze compares those: the package’s /usr/bin/scanelf is a different file.

Here the explanation is benign. Each Alpine release branch has its own build of every package, so the same version can hold different bytes, and sbomlyze notes that the base OS changed and a rebuild is expected. The reverse case is also visible: alpine-baselayout changed version (3.4.3-r2 → 3.6.5-r0) while all 10 of its hashed files stayed byte-identical.

With deny_owned_file_drift, the same finding fails a pipeline, which is what you want where the base image is pinned and nothing should touch package files after install.

What this does not prove. A same-version rebuild is expected across Alpine releases. Only the CycloneDX output lacks file ownership, so this check needs Syft JSON or SPDX.
