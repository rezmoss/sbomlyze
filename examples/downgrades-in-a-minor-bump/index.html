Downgrades hiding in a minor bump

Upgrading node:20.11.1-alpine to 20.18.0-alpine put older major versions of ansi-regex and strip-ansi at the same paths inside npm.

containernpmapk Location-aware matchingdeny_downgrades policynpm version ordering

What happened

npm ships with its own dependencies, many of them in several copies at different paths. sbomlyze tracks each copy by its path, so a package is only compared with the copy that sat at the same place before.

At /usr/local/lib/node_modules/npm/node_modules/ansi-regex the copy went from 6.0.1 to 5.0.1, and strip-ansi next to it from 7.1.0 to 6.0.1. npm rearranged its bundled tree between npm 10.2 and 10.8; it still works. Anything that resolves those two packages from that path now gets the older major version, and deny_downgrades catches it. The other 99 version changes are upgrades, including node itself, 20.11.1 → 20.18.0.

What this does not prove. npm rearranging its own bundled tree does not prove any application loads the older copy. It shows that the copy at that path is older.
